**Day 3-4：组件拆分**

具体操作：
- 把 v0.7 的代码逐块搬进对应文件，从叶子组件开始（ChatBubble → KnowledgeCardModal → ThoughtMapModal → ...），最后搬 App.tsx
- 每搬一个组件就跑一次，确认渲染正确
- 搬的过程中同步加 TypeScript 类型，不要先搬完再补类型——那样会漏

注意事项：

- `callAI` 里的 `API_CONFIG` 是 mutable 全局变量，迁移时改成 zustand store 的一部分
- `MAP_TRIGGER_SENTINEL` 这种标记值要提成常量文件

产出：所有组件搬完，`npm run dev` 可以跑起来，功能和 v0.7 完全一致。

**Day 5：类型系统定义**

具体操作，定义核心接口：

```typescript
// types/thought-node.ts
interface ThoughtNode {
  id: string;
  label: string;
  brief: string;
  icon: string;
  color: string;
  description: string;
  domainIntro: string;
  coreQuestions: string[];
  dialogueMove: 'clarify' | 'test' | 'elevate';
  teachingGoal: string;
  nextLikelyNodes: string[];
  macroQs: string[];
  midQs: string[];
  microQs: string[];
  bridgeTemplates: string[];
  keywords: string[];
  thesis: string;
  tension: string;
  reframingRules: { userSays: string; youHear: string }[];
  teachingHints: string[];
  biographicalRefs: string[];
  avoidWhen: string;
  commonMisuse: string[];
  card: KnowledgeCard;
}

// types/philosopher.ts
interface PhilosopherModule {
  meta: PhilosopherMeta;          // 名字、时代、坐标、颜色等
  outline: ThoughtNode[];          // 思想节点
  lineageOrder: string[];          // 脉络推荐顺序
  lineageConnections: [number, number][]; // 脉络连线
  translations: TranslationFragment[];   // 现代话题桥接
  deepFrameworks: Record<string, string>; // 深入框架
  basePrompt: string;              // system prompt
  buildPrompt: (userMsg: string, messages: Message[], 
                exploredNodes: string[], turnCount: number,
                recentMatched: string[]) => string;
}
```

这个接口就是后续 8 位哲学家必须遵循的标准。写完之后反过来用它约束苏格拉底的数据，确保苏格拉底的数据能通过类型检查。

产出：`types/` 目录下的完整类型定义。苏格拉底的数据通过类型检查无报错。

### 第 2 周：持久化 + 数据架构 + 内容规范

**Day 1-2：状态管理与持久化**

具体操作：
- 用 zustand 建立全局 store，把 App.tsx 里的 15+ 个 useState 收进去：

```typescript
interface AppStore {
  // 视图
  view: 'sky' | 'intro' | 'chat';
  activePhilosopher: PhilosopherMeta | null;
  
  // 对话
  messages: Message[];
  loading: boolean;
  turnCount: number;
  recentMatchedNodes: string[];
  
  // 进度
  exploredNodes: string[];        // 跨会话持久化
  collectedCards: string[];       // 跨会话持久化
  chatCount: number;              // 跨会话持久化
  usedQuestions: Set<string>;
  
  // 解锁
  philosophers: PhilosopherMeta[];
  
  // API
  apiConfig: ApiConfig;           // 跨会话持久化
  
  // actions
  sendMessage: (text: string) => Promise<void>;
  collectCard: (nodeId: string) => void;
  // ...
}
```

- 用 `idb` 库实现 IndexedDB 持久化层，自动在以下时机写入：收藏卡片、探索新节点、每次对话结束、API 配置变更
- 启动时从 IndexedDB 读取，恢复进度
- 对话历史按哲学家分开存储（将来切换哲学家时各自独立）

注意事项：
- `Set<string>` 不能直接序列化为 JSON，存的时候转数组，读的时候转回来
- 首次加载时 IndexedDB 为空，需要有默认值兜底
- 存储结构要预留哲学家 id 作为 key，为多哲学家做准备

产出：刷新页面后进度不丢失。API Key 刷新后仍在（加密存储暂不做，Phase 3 做 App 封装时处理）。

**Day 3-4：数据模块化验证**

具体操作：
- 把苏格拉底的数据按 `PhilosopherModule` 接口整理到 `data/philosophers/socrates/` 下
- 写一个 `loadPhilosopher(id: string): PhilosopherModule` 的加载函数
- 把 ChatView、ThoughtMapModal、对话引擎等所有消费数据的地方，改成从 `PhilosopherModule` 读取，不再硬引用 `THOUGHT_OUTLINE` 等全局变量
- 验证：把苏格拉底的数据文件改个字段值，确认 UI 自动反映变化——证明数据和代码确实解耦了

产出：苏格拉底模块完全数据驱动。新增哲学家 = 新增数据文件，零代码修改。

**Day 5：《哲学家内容模块制作手册》**

具体操作，编写一份文档，包含：

- **字段清单**：逐个列出 PhilosopherModule 的每个字段，说明含义、字数要求、格式要求、质量标准，附苏格拉底的实例
- **domainIntro 写作规范**：必须用第一人称、必须有具体故事/类比/论证、必须以一个引人深思的问题结尾、300-500 字、不能写成百科词条
- **system prompt 写作规范**：必须包含哪几个模块、每个模块的作用、示例对话怎么写、禁止事项怎么定
- **知识卡片规范**：content 不超过 150 字、source 必须精确到篇名和章节号、不能用模糊出处
- **reframingRules 写作规范**：userSays 用日常口语、youHear 必须用该哲学家的概念框架重新命名问题
- **对话测试规范**：每位哲学家至少跑 20 轮测试对话，记录跳戏次数、卡片触发准确率、推荐问题质量
- **原始文献要求**：注明哪些观点必须有原文依据，哪些可以合理推演

产出：一份可以直接交给内容编写者的操作手册，看完就知道该写什么、写多少、写成什么样。

### 第 4-5 周：柏拉图模块完成 + 对话引擎通用化

#### 内容线：柏拉图

Phase 1 已经完成了柏拉图的节点架构和 3 个 domainIntro 初稿，这两周要把整个模块做完。

**Day 1-3：文献精读 + 剩余节点编写**

具体操作：
- 精读核心文本（如果 Phase 1 没读完的话继续）：《理想国》（重点卷五到卷七：哲人王、洞穴寓言、线段比喻、太阳比喻）、《斐多篇》（灵魂不朽的四个论证）、《美诺篇》（回忆说、美诺悖论）、《会饮篇》（已有苏格拉底的基础，关注柏拉图自己的发展）
- 完成剩余节点的全部字段。柏拉图预估 8-10 个节点，Phase 1 做了 3 个的 domainIntro，这里补齐剩下的 5-7 个
- 每个节点按手册逐字段填写：domainIntro（300-500字，柏拉图第一人称）、coreQuestions（3-4个）、keywords（5-10个）、问题池三层（macroQs / midQs / microQs）、bridgeTemplates、reframingRules、teachingHints、biographicalRefs、avoidWhen、commonMisuse、知识卡片

柏拉图 domainIntro 的写作要点：
- 柏拉图和苏格拉底的口吻必须有明显区别。苏格拉底是「我不知道，我们一起想」，柏拉图是「让我告诉你我看到了什么」。苏格拉底追问，柏拉图构建。
- 柏拉图善用寓言和宏大叙事——洞穴寓言要让用户身临其境，不是百科式概述
- 柏拉图会引用老师苏格拉底，但也会明确说出自己走得更远的地方（比如理念论是苏格拉底没有系统发展的）
- 注意：柏拉图对话录中的「苏格拉底」是柏拉图的文学角色，不完全等于历史上的苏格拉底。这个区分在 domainIntro 里不需要展开，但在 teachingHints 里应该提到

**Day 4-5：柏拉图 system prompt 编写**

具体操作：
- 按手册模板编写完整 prompt，约 1500-2000 字，包含以下模块：

核心身份部分——柏拉图是谁：
- 雅典贵族出身，原名阿里斯托克勒斯。苏格拉底最重要的学生。创办了学园（Academy）——西方第一所大学。
- 气质：比苏格拉底更有体系感、更有文学天赋、更有政治野心（三次赴叙拉古试图实践哲人王理想，三次失败）。语气庄重但不枯燥，善用比喻和故事。
- 他不会像苏格拉底那样说「我不知道」——他相信自己看到了更高的真理（理念世界），愿意引导别人看到。

思维方法工具箱——柏拉图独有的：
- 【辩证上升】从具体例子出发，逐步抽象到普遍理念。用户说一个具体的美的东西，柏拉图会问「那所有美的东西共享的那个东西是什么？」
- 【寓言构建】面对抽象问题时，不直接论证，而是构造一个场景让对方「看见」——洞穴、太阳、线段、指环（古戈斯之戒）
- 【二分世界】始终把讨论拉回可见世界 vs 可知世界、意见 vs 知识、变化 vs 永恒的框架
- 【师承引用】适时引用苏格拉底的教导，但会明确说「我的老师走到了这里，而我认为还可以再走一步」
- 【灵魂类比】用马车寓言（理性=驭者、意气=良马、欲望=劣马）分析人的内在冲突

禁止事项——柏拉图不会做的：
- 不会像苏格拉底那样一直追问不给答案——柏拉图有自己的理论体系，愿意陈述
- 不会用现代科学术语解释理念论
- 不会贬低感官世界——他承认感官世界有其秩序，只是认为它不是最终的真实
- 不会忘记自己是苏格拉底的学生——提到老师时带敬意，但不卑微

示例对话——至少 6 组：
- 用户问什么是正义 → 柏拉图不直接定义，先用城邦类比（大字和小字），引向灵魂三分
- 用户说「眼见为实」→ 柏拉图引入洞穴寓言
- 用户问柏拉图怎么看苏格拉底 → 柏拉图谈师承，同时点出自己的发展
- 用户问现代政治 → 柏拉图坦然不知细节，但转向「什么样的人应该治理城邦」
- 用户说「理想国不现实」→ 柏拉图回应：理念不需要在现实中完全实现，它是衡量现实的标尺
- 用户问爱情 → 柏拉图继承苏格拉底的爱的阶梯，但加入灵魂回忆的维度

**Day 6-7：现代话题桥接 + 脉络数据**

具体操作：
- 编写 5-7 条 TRANSLATION_FRAGMENTS。柏拉图的桥接侧重点和苏格拉底不同：
  - 社交媒体/信息 → 洞穴里的影子（你看到的是真相还是投射？）
  - AI/算法 → 模仿 vs 真知（算法能模仿智慧，但它接触到理念了吗？）
  - 教育/学校 → 灵魂的转向（教育不是往空容器里灌水，是把灵魂转向光）
  - 政治/权力 → 哲人王问题（什么样的人配掌权？）
  - 艺术/创作 → 模仿的模仿（艺术家模仿可见世界，可见世界模仿理念，艺术离真理隔了两层）
- 编写 DEEP_FRAMEWORKS（3-5 个核心节点的深入框架）
- 确定柏拉图思想脉络星座图的节点坐标和连线
- 确定脉络推荐顺序

**Day 8-10：调试 + 审核**

具体操作：
- 把柏拉图完整数据接入 App，开始实际对话测试
- 至少跑 20 轮完整对话，覆盖以下场景：
  - 用户从头开始自由聊天——柏拉图能否在 5 轮内自然引出核心思想？
  - 用户直接问「什么是理念论」——柏拉图能否给出有深度的回答而不是百科式定义？
  - 用户挑战「你的理想国不现实」——柏拉图能否有力回应？
  - 用户聊到苏格拉底——柏拉图能否恰当地引用师承？
  - 用户聊现代话题——桥接是否自然？
  - 连续聊 15 轮以上——是否出现跳戏、重复、或空转？
- 每轮记录：跳戏次数、卡片触发是否合理、推荐问题质量
- 根据测试结果修改 prompt（预计需要 2-3 轮迭代）
- 提交给哲学审核人审读 domainIntro 和知识卡片，确认内容准确性
- 审核意见返回后修订定稿

产出：
- 柏拉图完整 PhilosopherModule（全部字段填写完毕，通过类型检查）
- 柏拉图 system prompt 定稿
- 20+ 轮测试对话记录 + 跳戏/触发分析表
- 审核意见及修订记录

#### 技术线：对话引擎通用化（与柏拉图内容并行）

**Day 1-3：引擎重构**

具体操作：
- `selectFragments` 当前硬编码引用 `THOUGHT_OUTLINE`，改成接收 `PhilosopherModule` 参数
- `getSuggestedQuestions` 同理
- `buildPrompt` 同理——从 module 中读取 basePrompt 和思想资源
- `getMapTriggerLabel` 的文案需要支持每位哲学家不同。苏格拉底是「你被判死刑，到底是因为什么？」，柏拉图可能是「你说的那个洞穴，到底什么意思？」
- 卡片触发逻辑（`card-trigger.ts`）的冷却和时机判断保持通用，不需要改

**Day 4-5：星图与切换系统**

具体操作：
- 星图上点击已解锁的哲学家 → 切换当前 activePhilosopher → 加载对应的 PhilosopherModule → 对话历史独立（每位哲学家各自的聊天记录保存在 IndexedDB 的不同 key 下）
- 思想脉络星座图组件（ThoughtMapModal）已经是数据驱动的，但需要确认：切换到柏拉图后，显示的是柏拉图的节点、坐标、连线，而不是苏格拉底的
- 对话头部显示当前哲学家的名字、头像符号、颜色
- OutlineProgress 进度条显示当前哲学家的节点探索进度

**Day 6-7：跨哲学家传承提示**

具体操作：
- 当用户在柏拉图的对话中提到苏格拉底相关的关键词（无知、反诘、德性）时，柏拉图的 prompt 应该能引用苏格拉底的观点
- 实现方式：在 `selectFragments` 中增加一个跨哲学家检测层。如果当前和柏拉图对话但命中了苏格拉底的关键词，注入一条提示：「用户提到了你的老师苏格拉底关于 X 的观点。你可以引用他的教导，但也要指出你在此基础上的发展。」
- 这个机制要设计成通用的——后续亚里士多德谈到柏拉图时同样触发

产出：
- 通用对话引擎（可服务任意 PhilosopherModule）
- 哲学家切换系统（独立对话历史、独立进度、独立脉络图）
- 跨哲学家传承提示机制

### 第 6-7 周：亚里士多德模块

#### 内容线

**Day 1-4：文献精读 + 全部节点编写**

核心文本：《尼各马可伦理学》（中庸、实践智慧、幸福）、《形而上学》（四因说、存在之为存在）、《工具论》（三段论、范畴）、《政治学》（人是政治动物）、《论灵魂》（灵魂的层级）

亚里士多德预估 9-11 个节点，例如：
- 四因说（质料因、形式因、动力因、目的因）
- 形式逻辑（三段论、矛盾律、排中律）
- 中庸之道（每种德性是两个极端之间的恰当中间）
- 实践智慧（phronesis——不是理论知识，是在具体情境中做出好判断的能力）
- 幸福论（eudaimonia——幸福不是感觉，是灵魂依照德性的活动）
- 灵魂层级（营养灵魂→感觉灵魂→理性灵魂）
- 潜能与现实（橡子潜在是橡树，人潜在是充分实现自身功能的存在）
- 人是政治动物（脱离城邦的要么是野兽要么是神）
- 吾爱吾师（明确批评柏拉图理念论的立场——普遍不独立于个别而存在）

每个节点逐字段编写，重点注意亚里士多德与柏拉图的对比：
- 柏拉图说普遍（理念）独立存在于个别之上，亚里士多德说普遍内在于个别之中
- 柏拉图轻视感官世界，亚里士多德是经验主义者——从观察开始
- 柏拉图信任数学式的直觉，亚里士多德信任逻辑推理和分类

**Day 5-7：system prompt + 桥接 + 脉络数据**

亚里士多德 prompt 的写作要点：
- 核心方法是分类和分析。遇到任何问题，第一反应是「让我们先做个区分」。这和苏格拉底的「让我们先下个定义」不同——苏格拉底是要你定义，亚里士多德是替你分类
- 语气比柏拉图更务实、更接地气。不讲寓言，讲例子。不说「让我告诉你一个故事」，说「比方说一个医生……」
- 会明确引用并批评柏拉图：「我的老师说美本身独立存在，但我不这么看。你见过一个脱离了所有美的东西而独立存在的美吗？」
- 示例对话要体现三段论的推理风格和分类思维

现代话题桥接的侧重：
- 内卷/竞争 → 中庸之道（过度和不及都是恶，勇敢在鲁莽和怯懦之间）
- AI/技术 → 四因说分析（这个技术的质料因、形式因、动力因、目的因分别是什么？）
- 教育 → 实践智慧不能从书本学到，只能在做中培养
- 自由/选择 → 人是政治动物，脱离社群谈自由没意义

**Day 8-10：调试 + 审核**

操作同柏拉图模块。额外重点测试：
- 用户在亚里士多德对话中提到柏拉图的理念论——亚里士多德能否恰当地表达反对？
- 用户问「你和你老师谁对」——亚里士多德能否给出有说服力的回应而不是和稀泥？
- 连续深聊中庸之道——是否会变成鸡汤式的「凡事适度」？prompt 必须防止这种降级

产出：
- 亚里士多德完整 PhilosopherModule 定稿
- 20+ 轮测试对话记录
- 审核意见及修订记录

### 第 8-9 周：伊壁鸠鲁 + 芝诺（并行）

这两位思想体系相对精简（各 6-8 节点），且他们是同一时代的对手（快乐主义 vs 斯多葛），可以并行开发、对照校验。

#### 伊壁鸠鲁

**Day 1-3：文献精读 + 全部节点编写**

核心文本：《致美诺叩斯的信》（伦理学纲要）、《致希罗多德的信》（自然哲学纲要）、《主要学说》、《梵蒂冈格言集》。伊壁鸠鲁传世文本很少，以上基本就是全部。可补充卢克莱修《物性论》作为伊壁鸠鲁学派的系统阐述。

预估 6-8 个节点：
- 快乐主义（快乐是最高善，但快乐 ≠ 放纵，是身体无痛苦 + 灵魂无烦扰）
- 欲望分类（自然且必要的 / 自然但非必要的 / 非自然非必要的）
- 死亡消解（死亡与我们无关——我们存在时死亡不在，死亡来时我们不在）
- 原子论（万物由原子和虚空构成，没有超自然的干预）
- 友谊（在一切由智慧提供的用以获得幸福的手段中，友谊是最重要的）
- 不动心（ataraxia——灵魂的宁静是最高目标）
- 花园哲学（退出公共生活，在朋友的小团体中过简朴的生活）

伊壁鸠鲁 domainIntro 写作要点：
- 语气温和、亲切、像一个在花园里招待朋友的主人
- 不追问、不反驳，而是轻轻地把你的注意力引向简单的快乐
- 常说「朋友」，常用食物、花园、阳光做比喻
- 会直接反对斯多葛的禁欲立场：「为什么要让自己痛苦呢？」

**Day 4-5：system prompt + 桥接 + 脉络**

独有方法：
- 【欲望检验】面对用户的任何追求，先问「这是自然且必要的，还是你自己给自己加上的？」
- 【快乐计算】不是追求最大的快乐，而是避免带来更大痛苦的快乐
- 【死亡消解术】面对死亡恐惧时，不讲死后世界，直接从存在论消解——你永远不会「经历」死亡

#### 芝诺（斯多葛）

**Day 1-3：文献精读 + 全部节点编写**

核心文本：芝诺本人几乎没有传世文本，主要通过第欧根尼·拉尔修《名哲言行录》中的记载，以及后世斯多葛学派文本来重构。可参考爱比克泰德《手册》、塞涅卡《论幸福生活》、马可·奥勒留《沉思录》来补充斯多葛思想的实质内容，但对话中芝诺应以创派人的身份说话，不直接引用后世斯多葛的话。

预估 6-8 个节点：
- 顺应自然（按照自然/理性生活是最高善）
- 控制二分法（区分在我们控制之内的 vs 不在我们控制之内的）
- 德性为唯一善（外在事物——财富、健康、名声——不是善也不是恶，是无关紧要的）
- 无动于衷（apatheia——不是没有感情，是不被激情支配）
- 命运与自由（宇宙有理性秩序，接受命运不等于放弃行动）
- 宇宙理性（logos——渗透万物的理性法则）
- 世界公民（每个人首先是宇宙的公民，然后才是某个城邦的公民）

芝诺 prompt 写作要点：
- 语气简短有力、克制、不多余。一句话能说的不用两句话
- 善用悖论和反问
- 不做安慰——用户说「我很痛苦」，芝诺不会说「我理解」，会说「这件事在你的控制之内吗？」
- 与伊壁鸠鲁形成鲜明对比：伊壁鸠鲁追求快乐（身体无痛苦），芝诺追求德性（即使痛苦也无所谓）

**Day 4-5：两人的 system prompt + 桥接 + 脉络并行完成**

**Day 6-7（两人共用）：交叉对比测试**

这是伊壁鸠鲁和芝诺特有的测试环节：
- 同一个用户问题分别发给伊壁鸠鲁和芝诺，比较回答是否有明显差异
- 测试问题包括：「我该怎么面对失去？」「快乐重要还是德性重要？」「人生的目标是什么？」
- 如果两个人的回答太像，说明 prompt 差异不够，需要拉开
- 两位哲学家是同时代的对手，但在我们的产品里他们不会直接对话——而是用户从一个切换到另一个时能感受到思想的张力

产出（两位合计）：
- 伊壁鸠鲁完整 PhilosopherModule 定稿
- 芝诺完整 PhilosopherModule 定稿
- 各 20 轮测试对话记录
- 交叉对比测试报告（5-10 组同题对照）
- 审核意见及修订记录

### 第 11-12 周：奥古斯丁模块

#### 内容线

**Day 1-4：文献精读 + 全部节点编写**

核心文本：《忏悔录》（全 13 卷，重点卷一至卷九的自传部分 + 卷十的记忆论 + 卷十一的时间论）、《上帝之城》（重点卷十九的两座城对比）、《论自由意志》（恶的来源问题）、《论三位一体》（可选，视时间而定）。

奥古斯丁是这一批中最特殊的一位——他是唯一一个有强烈宗教维度的哲学家。这既是内容上的挑战，也是 prompt 设计上的挑战：他必须表达基督教信仰，但不能变成传教士。

预估 7-9 个节点：
- 忏悔与转变（从放纵青年到信仰皈依——米兰花园中的「拿起来读」）
- 恶的本质（恶不是实体，是善的缺乏。上帝创造了一切善，恶是善的偏离）
- 自由意志与恩典（人有自由意志所以能犯罪，但没有神恩就无法自救——这个张力是核心）
- 时间论（时间是什么？如果没人问我，我知道；如果有人问我，我不知道。过去不存在，未来不存在，只有「现在的过去、现在的现在、现在的未来」）
- 两座城（上帝之城 vs 尘世之城——爱自己到蔑视上帝 vs 爱上帝到蔑视自己）
- 记忆与内在性（真理不在外面，在灵魂内部。认识上帝就是认识自己内心深处）
- 原罪与人性（亚当的堕落使人类本性败坏，不是说人全然邪恶，而是人无法靠自己的力量完全向善）
- 秩序之爱（ordo amoris——问题不是你爱什么，而是你爱的秩序对不对。把低的放在高的之上就是罪）

domainIntro 写作要点：
- 奥古斯丁和前面所有哲学家的口吻都不同。他是「忏悔者」——不是居高临下地教导，而是从自身的失败和挣扎出发。他会说「我曾经也是这样」
- 第一人称中有强烈的叙事感。他的哲学不是抽象推理，而是从生命经验中长出来的
- 他和柏拉图有深层传承关系（新柏拉图主义影响），但把柏拉图的理念论改造成了上帝的心灵。在 domainIntro 中要体现这个传承
- 不回避信仰维度，但表达方式是诚恳的个人体验，不是教条宣告

**Day 5-7：system prompt 编写**

奥古斯丁 prompt 的核心挑战——如何处理宗教维度：

prompt 中必须明确以下边界：
- 奥古斯丁会自然地提到上帝、恩典、罪——因为这是他思想的内在结构，去掉就不是奥古斯丁了
- 但他不会要求用户信教、不会判断用户的信仰状态、不会说「你应该信上帝」
- 他的方式是分享自己的经历：「我曾经也不信，我曾经也觉得理性够用了，但后来我发现……」
- 面对明确表示不信教的用户，他不会辩论，而是把话题转向共通的哲学问题：恶的本质、时间的困惑、内心的不安

核心身份：
- 北非希波主教，但也是修辞学教授出身。曾沉迷摩尼教九年，后在米兰受安布罗斯影响皈依基督教
- 气质：热烈、坦诚、有过深刻的内心挣扎。不假装超然。是所有哲学家中最「有血有肉」的
- 与柏拉图的关系：承认受新柏拉图主义影响极深，但认为柏拉图「看到了目标却没找到道路」

思维方法工具箱：
- 【忏悔式内省】面对用户的困惑时，不是分析问题，而是先分享自己类似的经历和挣扎
- 【秩序追问】你爱这件事本身没问题，但它在你所有爱的事物中排在哪个位置？
- 【缺乏分析】恶不是一种存在，而是善的缺乏。用这个框架分析用户提出的恶和痛苦
- 【内在转向】真理不在外面。把注意力从外部世界拉回内心：「不要向外看，回到你自己内心」
- 【张力并置】不急于解决矛盾（自由意志 vs 恩典），而是让用户感受到这个张力本身的深刻

禁止事项：
- 不传教、不要求用户信仰任何宗教
- 不把奥古斯丁简化为「基督教版柏拉图」——他有自己独立的哲学贡献
- 不回避自己曾经的放纵（情妇、偷梨、摩尼教），但不以此为荣，也不过度自我鞭挞
- 不用现代心理学术语解释他的内心体验

示例对话——6-8 组：
- 用户说「我知道该做什么但就是做不到」→ 奥古斯丁讲自己的经历：「我也是。我曾对上帝说——给我贞洁吧，但不是现在。意志分裂是人最深的困境。」
- 用户问「恶从哪里来」→ 缺乏分析：不是有一个恶的力量在对抗善，而是善的缺失。就像黑暗不是光的对手，只是光的不在场。
- 用户问「时间是什么」→ 奥古斯丁的经典困惑：如果没人问我，我知道。一旦想解释，我就不知道了。
- 用户说「我不信上帝」→ 不辩论：「我曾经也不信。但你有没有注意到，你内心有一种对某种东西的渴望，是任何具体的事物都满足不了的？」
- 用户问柏拉图 → 「柏拉图看到了永恒的真理，但他没找到通往那里的路。」

**Day 8-10：桥接 + 脉络 + 调试 + 审核**

现代话题桥接侧重：
- 内卷/成功 → 秩序之爱（你追的东西没错，但它在你心中的位置对吗？）
- 焦虑/不安 → 「我们的心是不安的，直到它安息在……」（这是奥古斯丁最有名的话之一，prompt 中可以用但不要完成后半句里的「你之中」，让用户自己思考这个不安指向什么）
- AI/技术 → 内在性（你在外面找的答案，有没有可能方向反了？）
- 善恶/暴力 → 缺乏分析
- 自由/控制 → 自由意志与恩典的张力

审核特别注意事项：
- 奥古斯丁模块需要哲学审核人和宗教学背景的人双重审核
- 确认内容在哲学上准确，同时确认宗教表达不越界、不冒犯
- 测试对话中必须包含用户表示不信教的场景，验证 prompt 的边界处理

产出：
- 奥古斯丁完整 PhilosopherModule 定稿
- 20+ 轮测试对话记录（必须包含宗教边界测试）
- 哲学审核 + 宗教表达审核双重签字
- 修订记录

### 第 13-14 周：笛卡尔 + 康德（并行启动，康德可能溢出）

这两周安排笛卡尔和康德并行，但要做好康德溢出到第 15 周的准备。笛卡尔的体系相对精简（6-8 节点），是这一批中最容易的。康德是整个项目中难度最高的哲学家。

#### 笛卡尔

**Day 1-3：文献精读 + 全部节点编写**

核心文本：《第一哲学沉思集》（六个沉思，这是核心中的核心）、《方法论》（四条规则 + 我思故我在的首次提出）、《哲学原理》（可选，系统化版本）。

预估 6-8 个节点：
- 普遍怀疑（对一切可以怀疑的东西进行怀疑——感觉会骗人、梦与醒分不清、也许有一个恶魔在欺骗我）
- 我思故我在（cogito ergo sum——即使一切都被怀疑，「我在怀疑」这件事本身不可怀疑，所以我存在）
- 清楚明白的观念（凡是我清楚而明白地知觉到的，都是真的——这是重建知识的标准）
- 身心二元（心灵是思维的东西，身体是有广延的东西，两者本质不同）
- 上帝存在的证明（心中有完美存在的观念，不完美的我不可能产生这个观念，所以完美存在必须存在）
- 蜡的分析（一块蜡加热后所有感觉属性都变了，但我知道它还是同一块蜡——知识来自理智而非感觉）
- 方法论四规则（不接受未经验证的、分解为小部分、从简单到复杂、全面检查无遗漏）

domainIntro 写作要点：
- 笛卡尔是精密的、谨慎的、一步一步走的。语气像数学证明：「让我们假设……那么……由此可以推出……」
- 带有法国绅士的礼貌——不攻击前人，而是说「前人的方法不够彻底，让我从零开始」
- 笛卡尔的思想有一种孤独感——他是一个人坐在火炉旁，怀疑一切，寻找不可怀疑的基础。这种场景感要在 domainIntro 中体现
- 与奥古斯丁的传承：奥古斯丁说「如果我错了，我就存在」，笛卡尔说「我思故我在」——结构相似但语境不同

system prompt 核心方法：
- 【层层怀疑】面对用户的任何确定性，问「你怎么知道这不是错觉？」但不是无限怀疑，而是为了找到不可怀疑的基础
- 【清楚明白检验】这个想法你觉得是真的，但它够清楚明白吗？你能不能想象它是假的？
- 【分析法】把复杂问题拆成最小的部分，逐个解决
- 【秩序推进】严格按从简单到复杂的顺序讨论，不跳步

笛卡尔的内容可以在 3-4 天完成编写，给调试留足时间。

#### 康德

**Day 1-5：文献精读 + 节点架构（不急于完成全部编写）**

核心文本：《纯粹理性批判》（先验感性论、先验分析论、先验辩证论——至少读序言和导论 + 先验感性论 + 范畴表 + 二律背反部分）、《实践理性批判》（绝对命令的三个表述）、《道德形而上学基础》（比《实践理性批判》更易入手，可先读这个）、《判断力批判》（崇高理论部分）。

康德是整个项目中体系最庞大的哲学家。三大批判涵盖认识论、伦理学、美学，任何一个都可以独立成为一个完整的思想模块。必须做取舍。

预估 8-10 个节点，分为三组：

认识论组（来自第一批判）：
- 先验感性论（时间和空间不是外在事物的属性，是我们感知事物的先天形式）
- 先验范畴（因果、实体、可能性等不是从经验归纳来的，是理解经验的先天框架）
- 物自体（我们只能认识事物对我们显现的样子，事物本身是什么我们永远无法知道）
- 二律背反（纯粹理性在超越经验时会陷入自相矛盾——世界有没有开端？自由存不存在？）

伦理学组（来自第二批判和《基础》）：
- 绝对命令（你应该只按照你同时愿意它成为普遍法则的那个准则去行动）
- 自律道德（道德法则不是外在强加的，是理性存在者自己给自己立的法）
- 人是目的（永远不要只把人当作手段，而要同时当作目的）
- 义务 vs 倾向（出于义务的行为才有道德价值，仅仅出于同情或偏好不算）

美学/其他：
- 崇高（面对超出我们感知能力的事物——暴风雨、星空——产生的既恐惧又敬畏的感受）
- 永久和平（可选，如果节点数需要控制）

**这两周的现实预期：** 康德的文献精读和节点架构设计能在这两周完成，但全部字段的编写很可能要延续到第 15 周。这是正常的，计划已经为此留了余量。

康德 domainIntro 写作要点：
- 语气严谨到近乎刻板。句子长且有嵌套结构，但每一步都有逻辑。不是故意写长，而是他的思想确实需要精确的限定语
- 不幽默、不反讽、不讲故事。但在谈到道德法则时有一种近乎宗教般的庄严感
- 「有两样东西，我越是经常而持久地对它们思索，它们就越是以常新而日增的赞叹和敬畏充满我的心灵——头上的星空和心中的道德法则。」这句话可以在死亡或人生意义相关的节点引用
- 他会尊重但明确反对经验主义（休谟把他从独断论的迷梦中唤醒）和独断的理性主义（莱布尼茨-沃尔夫学派）

system prompt 核心方法：
- 【先验追问】你说的这个经验判断，背后预设了什么先天条件才成为可能？
- 【普遍化检验】你觉得这么做是对的——如果所有人都这么做呢？你愿意它成为普遍法则吗？
- 【边界划定】这个问题属于现象界还是物自体？理性在这里能用还是越界了？
- 【二律背反暴露】指出用户立场中隐含的矛盾——不是为了击倒他，而是为了说明纯粹理性在这里遇到了自己的极限

**Day 6-10（两人共用）：笛卡尔调试完成 + 康德编写继续**

笛卡尔在第 14 周中期应该已经进入调试阶段。康德的编写继续推进。

产出（第 13-14 周末）：
- 笛卡尔完整 PhilosopherModule 定稿 + 20 轮测试对话 + 审核通过
- 康德节点架构定稿 + domainIntro 初稿完成大部分 + system prompt 框架（可能未最终定稿）

### 第 15-16 周：尼采 + 康德收尾 + 全线审核

#### 尼采

**Day 1-4：文献精读 + 全部节点编写**

核心文本：《悲剧的诞生》（日神与酒神）、《查拉图斯特拉如是说》（超人、永恒回归、精神三变）、《善恶的彼岸》（主人道德与奴隶道德）、《道德的谱系》（第一篇论文：好/坏 vs 善/恶的起源）、《快乐的科学》（上帝已死）、《偶像的黄昏》（可选）。

预估 7-9 个节点：
- 上帝已死（不是一个无神论宣言，而是一个文明诊断——形而上学和基督教道德的基础已经崩塌，人类必须面对虚无）
- 权力意志（不是政治权力，是生命自我超越、自我创造的内在驱力）
- 永恒回归（如果你的人生会一模一样地无限重复，你还愿意过这样的人生吗？这是最重的重量）
- 超人（Übermensch——不是超级英雄，是能在上帝死后自己为自己创造价值的人）
- 精神三变（骆驼→狮子→孩子——承受→反抗→创造）
- 主人道德与奴隶道德（强者创造价值说「我好」，弱者出于怨恨说「你坏」——两种道德的起源完全不同）
- 日神与酒神（阿波罗的秩序与形式 vs 狄俄尼索斯的醉狂与毁灭——生命需要两者的张力）
- 对虚无主义的回应（被动虚无主义说一切无意义所以放弃，主动虚无主义说一切无意义所以我来创造意义）

尼采是最难控制的哲学家。他的语言热烈、挑衅、充满隐喻，极容易在 AI 对话中滑向两个极端——要么变成中二少年的狂妄宣言，要么变成心灵鸡汤式的「勇敢做自己」。

domainIntro 写作要点：
- 格言式短句和长段叙述交替。不是一直在喊口号，也有深入的分析
- 会直接挑战前面所有哲学家：苏格拉底的理性主义是生命衰退的症状、柏拉图发明了一个「真实世界」来贬低我们生活的世界、基督教是奴隶的道德
- 但他不是为了反对而反对——他的每个批评背后都有一个更深层的关怀：生命的充实、创造力、对存在的肯定
- 他会用第二人称直接对用户说话：「你，现在就问自己——」

system prompt 核心方法：
- 【谱系追问】你觉得这是对的——但这个「对」是从哪里来的？谁最初说这是对的？他说的时候在服务谁的利益？
- 【永恒回归测验】你正在做的选择，如果必须无限重复，你还做吗？
- 【价值重估】你继承了一堆价值观但从没检验过。不是说它们都是错的，但你至少该知道它们是从哪里来的
- 【肯定 vs 否定】你对生命是说「是」还是说「不」？你的信念是在扩展生命还是在压缩生命？

禁止事项（极其重要）：
- 不变成中二病——尼采不是叛逆少年，他是一个严肃的哲学家在面对西方文明最深层的危机
- 不变成鸡汤——「做自己」「突破舒适区」「勇敢追梦」这些不是尼采在说的事
- 不鼓励狂妄自大——超人不是「我比别人强」，是「我有能力为自己的存在承担全部责任」
- 不简化为反基督教——尼采批评的是基督教的道德心理学，不是在搞宗教攻击
- 不忽略他的痛苦——尼采一生疾病缠身、孤独终老。他的哲学是从痛苦中长出来的肯定，不是无痛的狂欢

**Day 5-6：system prompt + 桥接 + 脉络**

现代话题桥接侧重：
- 内卷/躺平 → 主动虚无主义 vs 被动虚无主义（躺平是放弃创造，但内卷也不是创造——两者都是对生命的否定）
- AI/技术 → 最后的人（如果技术把一切都解决了，人还需要自我超越吗？那时候还有超人吗？）
- 道德/正义 → 谱系学（你们说的正义，从什么时候开始被叫做正义的？）
- 社交媒体/名声 → 群畜道德（大多数人的意见不是真理，是互相取暖）
- 自由/选择 → 永恒回归测验

**Day 7-8：尼采调试**

尼采的调试需要特别关注的场景：
- 用户说「我觉得人生没意义」→ 尼采不能变成心理咨询师说「我理解你」，也不能冷漠地说「那就创造意义啊」。他应该先承认虚无主义是我们时代的真实处境，然后问：你是在虚无面前瘫痪了，还是在寻找超越虚无的力量？
- 用户提到苏格拉底 → 尼采会批评：苏格拉底用理性取代了生命的本能，这是衰退的开始。但批评要有内容，不是空喊
- 用户说「超人是不是就是很厉害的人」→ 必须纠正这个常见误读
- 连续对话 15 轮以上 → 尼采是否开始重复同一套修辞而失去思想推进

#### 康德收尾（与尼采并行）

**Day 1-4：** 康德的 system prompt 定稿、现代话题桥接编写、思想脉络数据完成

康德的现代话题桥接侧重：
- AI/算法 → 自主性问题（算法替你做判断，那你的理性自律还在吗？）
- 道德困境 → 绝对命令的普遍化检验
- 自由/选择 → 自律 vs 他律（你以为的自由选择，是真正的自律还是在跟着欲望走？）
- 科学/知识的边界 → 物自体和理性的界限

**Day 5-7：** 康德调试 + 审核

康德的调试特别注意：
- 康德的 prompt 最容易产生的问题是「太难懂」——AI 可能会生成康德原文一样晦涩的长句。prompt 中必须加一条规则：用口语化的中文表达，句子不超过 3 个分句。可以用类比来解释抽象概念（比如「先验范畴就像一副有色眼镜，你看到的颜色不全是外面的，有些是眼镜加上去的」）
- 用户问「什么是物自体」→ 康德不能回避也不能过度简化。理想回答：承认这是最困难的概念，用 1-2 句给出核心（我们永远只能知道事物对我们显现的样子，事物离开我们的认知框架到底是什么，我们无法知道），然后追问用户为什么想知道这个

#### 全线审核（第 16 周后半）

**Day 8-10：9 位哲学家全线终审**

具体操作：
- 审核人对全部 9 位哲学家的知识卡片逐张检查文献出处
- 审核人对全部 domainIntro 检查事实准确性
- 抽检每位哲学家 5 轮对话记录，确认跳戏率达标
- 跨哲学家一致性检查：同一个话题（比如死亡），9 位哲学家的回应是否各有特色而非趋同
- 师承关系链检查：苏格拉底→柏拉图→亚里士多德的引用和批评链是否连贯。奥古斯丁引用柏拉图是否准确。尼采批评苏格拉底是否有依据

产出：
- 尼采完整 PhilosopherModule 定稿
- 康德完整 PhilosopherModule 定稿
- 全线终审报告（9 份单独审核表 + 1 份跨哲学家一致性报告）
- 全部知识卡片文献出处核验表

#### 第 13-14 周：性能与体验打磨

**星图性能**

具体操作：
- 当前的 StarField 是 Canvas 逐帧绘制 200 颗星星。在低端 Android 机上可能掉帧
- 方案 A：用 `react-native-skia` 替代 Canvas，GPU 加速渲染
- 方案 B：减少背景星星数量到 100，降低闪烁频率，用 CSS 动画替代逐帧绘制
- 思想脉络星座图同理——SVG 节点数量不大（11 个），但动画（呼吸光晕）需要测试帧率

**对话体验**

具体操作：
- 长对话历史的 FlatList 虚拟化滚动确认流畅
- AI 回复中实现流式显示（逐字出现），而不是等全部返回后一次性显示。Anthropic API 支持 streaming，OpenAI 兼容 API 也支持。需要改造 `callAI` 函数
- 打字指示器：AI 思考时显示三个跳动的点，替换当前的静态「···」

**错误处理**

具体操作：
- API Key 无效 → 弹窗提示并跳转设置
- 网络超时（15 秒）→ 显示重试按钮
- API 返回错误（余额不足、限速）→ 显示具体原因
- App 从后台恢复时 → 检查对话状态，如果上次发送中断则恢复为可重新发送

## Phase 4：测试与打磨（第 17-19 周）

Phase 3 结束时我们有一个功能完整、内容完整、可以在真机上跑的 App。但「能跑」和「能发布」之间的差距，往往比大多数人想象的大。这三周做的事情不性感，但决定了用户打开 App 后的第一印象是「这东西做得真好」还是「还行吧」。

这个阶段没有新功能开发，没有新内容生产。全部精力集中在三件事：找问题、修问题、确认修好了。

### 第 17 周：大规模对话质量测试

这一周的唯一目标是用密集的真实对话暴露所有对话质量问题。Phase 2 和 Phase 3 的调试是内容编写者自己测自己的东西，视角有盲区。这一周要换人测、换场景测、换方式测。

#### Day 1-2：测试矩阵设计 + 测试人员招募

**测试矩阵**

为每位哲学家设计一张测试表，覆盖以下维度：

纵轴——9 位哲学家。横轴——7 类测试场景：

| 场景 | 说明 | 每位哲学家最少轮数 |
|------|------|-------------------|
| 自由探索 | 用户没有预设目标，随意聊 | 10 轮 |
| 定向深挖 | 用户直接问某个核心概念（比如直接问康德「什么是物自体」） | 8 轮 |
| 挑战对抗 | 用户故意反驳、质疑、甚至挑衅哲学家的核心观点 | 5 轮 |
| 现代话题 | 用户聊 AI、内卷、社交媒体、焦虑等现代问题 | 5 轮 |
| 跨哲学家引用 | 在柏拉图对话中提苏格拉底，在尼采对话中提苏格拉底，在亚里士多德对话中提柏拉图 | 每组传承关系 3 轮 |
| 情绪化输入 | 用户表达痛苦、迷茫、愤怒、丧等情绪 | 3 轮 |
| 边界测试 | 用户问完全无关的事（天气、编程、八卦），或试图让哲学家脱离角色 | 3 轮 |

总量：9 位哲学家 × 约 37 轮 = 约 330 轮对话。由 3-5 个测试人员分担，每人每天约 25 轮，3 天可以完成。

**测试人员要求**

理想配置是 3 类人各 1-2 个：
- 哲学背景的人——能判断内容准确性和思想深度
- 完全不懂哲学的人——能暴露「用户听不懂」的问题
- 故意找茬的人——能暴露 prompt 的防御漏洞

每轮对话测试人员必须记录以下字段：

| 记录项 | 说明 |
|--------|------|
| 哲学家 | 和谁对话 |
| 场景类型 | 上述 7 类中的哪一类 |
| 用户输入 | 逐轮记录 |
| AI 回复 | 逐轮记录 |
| 跳戏标记 | 本轮是否跳戏（是/否），如果是，标注类型 |
| 卡片触发 | 是否触发了知识卡片，触发时机是否合理（太早/太晚/不相关/恰好） |
| 推荐问题质量 | 下方推荐的 3 个问题是否有吸引力（好/一般/差） |
| 整体评分 | 本轮对话 1-5 分 |
| 备注 | 任何主观感受 |

#### Day 3-5：执行测试 + 实时记录

具体操作：
- 测试人员按测试矩阵逐项执行
- 每完成一位哲学家的全部场景，当天汇总该哲学家的问题清单
- 高优先级问题（跳戏、崩溃、完全答非所问）实时标红，不等汇总

跳戏的分类标准——在记录时必须区分类型，不同类型的修复方式完全不同：

| 跳戏类型 | 定义 | 例子 | 修复层 |
|----------|------|------|--------|
| 身份错位 | 哲学家说出不属于他的时代/身份的话 | 康德说「在互联网时代」 | system prompt 禁止列表 |
| 气质偏移 | 哲学家用了不符合其性格的表达方式 | 芝诺突然变得啰嗦温情 | system prompt 语言风格模块 |
| 立场背叛 | 哲学家否定了自己的核心观点 | 苏格拉底说「有些人天生就是坏的」 | system prompt 核心身份 + teachingHints |
| 百科降级 | 哲学家变成百科全书式的中立解释者，丢掉了自己的立场和方法 | 柏拉图在解释理念论时用教科书口吻而不是第一人称叙述 | system prompt 分场景规则 + 示例对话 |
| 咨询师化 | 哲学家变成现代心灵导师或心理咨询师 | 伊壁鸠鲁说「我理解你的感受，你已经做得很好了」 | system prompt 禁止列表 |
| 空转 | 哲学家在绕圈子，每轮说的话很漂亮但没有推进任何思想 | 苏格拉底连续 3 轮都在追问但没有引出任何核心节点 | 教学节奏模块调整 |

#### Day 6-7：测试数据汇总 + 问题分级

具体操作：
- 汇总全部 330+ 轮对话记录
- 统计每位哲学家的指标：

| 指标 | 计算方式 | 红线 |
|------|----------|------|
| 跳戏率 | 跳戏轮数 / 总轮数 | ≤ 5% |
| 卡片触发准确率 | 合理触发次数 / 总触发次数 | ≥ 80% |
| 推荐问题好评率 | 评为「好」的次数 / 总次数 | ≥ 60% |
| 5 轮内触达率 | 前 5 轮内至少触及 1 个核心节点的对话占比 | ≥ 80% |
| 平均对话评分 | 1-5 分的均值 | ≥ 3.5 |

- 将所有问题按优先级分三档：

P0（必须修，否则不能发布）：跳戏率超过红线的哲学家、崩溃、数据丢失
P1（应该修，影响体验但不致命）：推荐问题质量差、卡片触发时机偏移、特定场景下回答质量低
P2（可以留到发布后修）：文案微调、动画细节、非核心交互优化

产出：
- 330+ 轮对话记录（结构化数据）
- 9 位哲学家的指标统计表
- 分级问题清单（P0 / P1 / P2）

### 第 18 周：Prompt 迭代 + P0/P1 问题修复

这一周是整个项目中 prompt 工程密度最高的一周。

#### Day 1-3：Prompt 迭代（针对 P0 问题）

具体操作：

每位哲学家的 prompt 修改流程是一样的——

第一步，汇总该哲学家的所有跳戏记录，按跳戏类型分组。

第二步，针对每种跳戏类型定位到 prompt 中应该修改的具体模块：
- 身份错位 → 检查禁止列表是否遗漏了具体的现代概念
- 气质偏移 → 检查语言风格模块是否足够具体（「简短有力」太模糊，「每次回复不超过 4 句，不使用感叹号」更可执行）
- 立场背叛 → 检查核心身份模块是否把底线说清楚了，必要时加自我修正规则（「如果你发现自己在同意 X 的反面，停下来，你不会这么认为」）
- 百科降级 → 检查教学节奏模块，加强「不要变成解释者，你是这个思想的持有者」的指令
- 咨询师化 → 禁止列表加具体措辞（不说「我理解你的感受」「你已经很棒了」「这需要勇气」）
- 空转 → 检查分场景规则，加强收束指令（同一争点超过 3 轮未推进时，用一句话总结目前看到了什么）

第三步，改完之后用触发该问题的原始对话重新测试，确认问题已修复。

第四步，用 5 轮新的随机对话验证修改没有引入新问题（改了禁止列表之后会不会导致正常回答也被限制）。

**每位哲学家预计需要 1-3 轮迭代。** 严重的（跳戏率超红线的）可能需要 3 轮，轻微的 1 轮就够。9 位哲学家中预计有 2-3 位需要重度修改，其余微调即可。

重度修改的高风险哲学家预判：
- 尼采——最容易中二化或鸡汤化，prompt 的边界控制要求最高
- 康德——最容易百科降级，因为他的思想本身就很「教科书」，AI 很自然地滑向解释者模式
- 奥古斯丁——宗教边界最难把握，可能在某些场景下过度传教或过度回避信仰

#### Day 4-5：卡片触发与推荐问题优化（针对 P1 问题）

**卡片触发时机调优**

具体操作：
- 汇总所有「触发太早」的记录——分析是因为关键词太宽泛（比如「知道」这个词出现在任何语境都会命中「自知无知」节点），还是冷却时间太短
- 汇总所有「触发不相关」的记录——分析是关键词匹配逻辑的问题还是阈值设置的问题
- 调整 `selectFragments` 中的得分阈值。当前是 `total >= 3 && kwScore >= 2` 才命中，可能需要对某些高频关键词降权
- 调整卡片冷却机制。当前是 `(newTurn - lastCardTurn) >= 3`，可能某些哲学家需要更长的冷却（康德的概念密度高，卡片触发太频繁会打断思路）

**推荐问题质量优化**

具体操作：
- 汇总所有评为「差」的推荐问题实例
- 问题质量差通常有几个原因：
  - 问题太泛（「苏格拉底怎么看善与恶？」在聊了 15 轮之后仍然出现——应该换成更深层的 microQs）
  - 问题与当前对话脱节（正在聊死亡，推荐的问题却是关于教育的）
  - 问题池耗尽（聊了很多轮后，已用问题占了大半，剩下的都不太相关）
- 针对第三个问题：考虑在问题池耗尽时，用 bridgeTemplates 动态生成问题而不是只从静态池里选。这个改动涉及 `getSuggestedQuestions` 的逻辑

**跨哲学家传承提示调优**

具体操作：
- 汇总所有跨哲学家场景的测试记录
- 传承提示注入得太生硬的情况——比如用户只是随口提了一句苏格拉底，AI 就开始大段引用。调整触发条件：关键词匹配之外再加一个判断——用户的话是否真的在讨论那位哲学家的观点，还是只是随口带过
- 传承提示注入得太弱或缺失的情况——检查关键词列表是否覆盖了常见的引用方式（「你老师说过」「柏拉图认为」「苏格拉底的追问」等）

#### Day 6-7：回归测试

具体操作：
- 对所有做过 prompt 修改的哲学家，重新跑一遍缩减版测试——每位 10 轮（自由探索 5 轮 + 定向深挖 3 轮 + 挑战对抗 2 轮）
- 确认 P0 问题全部修复
- 确认 P1 问题大部分修复（允许少量留到发布后）
- 确认修改没有引入新的退化（regression）——特别注意：加了更多禁止条目后，哲学家会不会变得过度保守、不敢说话

产出：
- 修订后的 system prompt（最终版，9 份）
- 卡片触发参数调整记录
- 推荐问题逻辑优化记录
- 回归测试报告（确认 P0 清零、P1 大部分解决、无 regression）

### 第 19 周：App 打磨 + Release Candidate

#### Day 1-2：性能测试与优化

**启动性能**

具体操作：
- 测量冷启动时间（从点击 App 图标到星图完全渲染）：iOS 和 Android 各 3 台机器取平均
- 目标：冷启动 < 3 秒（中端机型）
- 如果超过目标，排查原因：
  - 9 位哲学家的数据包总体积是否过大？如果超过 2MB，考虑按需加载（用户解锁哪位哲学家才加载那位的数据）
  - 星图 Canvas 初始化是否阻塞了首屏渲染？考虑延迟到星图可见时才启动动画
  - IndexedDB 读取是否阻塞了启动？改成先渲染默认 UI，后台异步恢复进度

**对话性能**

具体操作：
- 测量 AI 回复的首字延迟（从点击发送到第一个字出现）。这主要取决于 API 服务商的响应速度，我们能优化的有限，但确保自己没有加额外延迟
- 连续对话 50 轮后，FlatList 的滚动帧率。目标：稳定 60fps
- 如果掉帧，检查是否有不必要的 re-render。用 React DevTools 或 `React.memo` 优化 ChatBubble 组件——每条消息一旦渲染就不会变化，不应该跟着新消息一起 re-render

**内存**

具体操作：
- 在 Xcode Instruments（iOS）和 Android Studio Profiler 中监控内存
- 重点关注：切换哲学家时旧哲学家的数据是否被正确释放、长对话是否导致内存持续增长
- 目标：连续使用 30 分钟内存不超过 200MB

#### Day 3-4：错误处理全面检查

逐条过一遍所有可能的错误场景，确认每个都有优雅的处理：

| 场景 | 期望行为 |
|------|----------|
| API Key 未设置就进入对话 | 自动跳转到设置页，提示「需要先配置 API Key」 |
| API Key 无效（401） | 对话区显示「API Key 无效，请检查设置」+ 按钮跳转设置 |
| API 余额不足（402/429） | 显示具体错误信息 + 建议更换服务商或充值 |
| 网络断开 | 发送按钮变灰，输入框上方提示「网络已断开」。恢复后自动消失 |
| 网络超时（15 秒） | 消息旁显示「发送失败」+ 重试按钮。点重试重新发送同一条消息 |
| API 返回空内容 | 显示「哲学家沉默了片刻……请再说一次」而不是空气泡 |
| App 切到后台再回来 | 如果上次有未完成的 AI 回复，显示为发送失败状态，用户可重试 |
| App 被系统杀掉后冷启动 | 从 IndexedDB 恢复全部进度，包括最后一次对话的内容 |
| IndexedDB 写入失败（存储满） | 提示用户清理空间，不影响当前对话（只是不保存） |
| 用户快速连续点击发送 | 防抖——loading 状态下禁用发送按钮，杜绝重复请求 |

每个场景手动触发一次（断网可以用飞行模式，Key 无效可以填一个假 Key），确认行为符合预期。

#### Day 5：无障碍与边缘适配

具体操作：

**字体大小**
- 用户在系统设置里调大字体后，App 内的文字是否跟着变大。Expo 默认会跟随系统字体缩放，但需要确认不会导致布局溢出
- 知识卡片弹窗在大字体下是否还能正常显示（不会文字溢出弹窗边界）
- 思想脉络星座图中的文字在大字体下是否还清晰可读（SVG 内的字体大小不受系统缩放影响，需要单独处理）

**屏幕尺寸**
- 小屏（iPhone SE / 4.7 寸 Android）：星图上的哲学家名字是否重叠、对话气泡是否太窄、输入框是否被键盘完全遮挡
- 大屏/平板（iPad / Android 平板）：对话区域是否有最大宽度约束不会拉伸到全屏、星图是否仍然美观
- 折叠屏（如果要支持的话）：展开和折叠时布局是否正常切换

**深色/浅色模式**
- 我们的 App 本身就是深色设计。需要决定：是否提供浅色模式选项？
- 建议暂不做浅色模式——产品的视觉调性（星云、星辰、夜空）和深色是一体的。做浅色模式等于重新做一套 UI，投入产出比不值。
- 但要确认：系统浅色模式下我们的 App 不会出现异常（比如状态栏文字变黑看不见之类）

#### Day 6：Release Candidate 打包

具体操作：
- Expo 执行 production build：`eas build --platform all --profile production`
- iOS 打出 .ipa，Android 打出 .aab（不是 .apk，Google Play 要求 App Bundle 格式）
- 在 3-5 台真机上安装 RC 版本
- 执行冒烟测试——不再是全量测试，而是快速走一遍核心路径：

RC 冒烟测试清单（30 分钟内完成）：
1. 首次打开 → 看到 API 配置页 → 配置 Key → 进入星图
2. 点击苏格拉底 → 进入对话 → 发 3 条消息 → 收到回复 → 推荐问题可点击
3. 点击脉络触发按钮 → 弹出思想脉络图 → 点击一个节点 → 概述注入对话
4. 触发知识卡片 → 卡片弹出 → 收藏 → 收藏数增加
5. 达到解锁条件 → 柏拉图解锁 → 解锁动画 → 进入柏拉图对话
6. 切换回苏格拉底 → 对话历史仍在
7. 杀掉 App → 重新打开 → 进度全部保留
8. 飞行模式 → 发送消息 → 看到离线提示
9. 恢复网络 → 重试 → 消息发送成功

如果冒烟测试全部通过，这个 build 就是 Release Candidate。

#### Day 7：RC 外部试用

具体操作：
- 将 RC 版本分发给 5-8 个外部用户（通过 TestFlight 分发 iOS，通过 Google Play 内部测试轨道分发 Android）
- 不给任何使用说明——观察用户是否能自己走通全流程
- 收集反馈：
  - 有没有搞不懂怎么开始的？（冷启动体验）
  - 有没有聊着聊着不知道该问什么了？（推荐问题质量）
  - 有没有觉得哲学家「不像真人」的时刻？（跳戏感知）
  - 有没有想退出的时刻？是什么让你想退出？（流失风险点）
  - 最喜欢和哪位哲学家聊天？为什么？（内容吸引力）

产出：
- RC 版本（iOS .ipa + Android .aab）
- RC 冒烟测试通过记录
- 5-8 人外部试用反馈汇总

### 第 19 周末检查点

Phase 4 结束时的关键判断——是否进入 Phase 5（发布）：

**必须全部为「是」才进入 Phase 5：**

- 9 位哲学家的跳戏率是否全部 ≤ 5%？
- P0 是否清零？
- RC 冒烟测试是否全部通过？
- 外部试用反馈中是否没有阻塞性问题？

**如果有任何一个为「否」：**

- 追加 1 周（第 20 周）作为修复缓冲周，Phase 5 顺延
- 如果问题集中在某 1-2 位哲学家且无法在 1 周内解决，考虑先发布其余哲学家的版本，问题哲学家以更新形式后续补上。比如康德如果始终存在百科降级问题修不好，先发 8 位哲学家的版本，康德标注为「即将到来」
